# TripWise AI

An intelligent travel-planning concierge (college AI project): FastAPI backend with explainable AI components, React + Tailwind frontend in a purple-and-gold travel-magazine style.

> **Honesty note.** Destinations, attractions, stays and transport come from an **illustrative sample dataset** generated by `datasets/build_sample_data.py` (16 Indian destinations, 99 attractions, 80 fictional stays, 478 modelled transport links). Coordinates are approximate; fees and fares are estimates; stays are fictional. There are no live prices, availability or bookings. The only real external dataset used is Stravl-Data, for the optional ML component. See `docs/DATASETS.md`.

## Quick start

Requirements: Python 3.11+ and Node 20+.

```bash
# 1. backend
cd backend
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
PYTHONPATH=. python -m pytest tests -q            # 185 tests
PYTHONPATH=. uvicorn app.main:app --port 8000     # API at http://localhost:8000/api

# 2. frontend (second terminal)
cd frontend
npm install
npm run dev                                       # http://localhost:5173 (proxies /api to :8000)
```

Single-process demo: `cd frontend && npm run build`, then start uvicorn as above and open http://localhost:8000 (the backend serves `frontend/dist`).

Optional: regenerate data with `python datasets/build_sample_data.py`; retrain the ML model with `cd backend && PYTHONPATH=. python -m app.ml.stravl_pipeline` (needs `datasets/raw/Stravl_Travel_Preference_Data.csv`, which is git-ignored; see `datasets/raw/STRAVL_README.md`). Environment variables: `.env.example`.

## Chatbot
Intents: destination recommendation and info, accommodation search (type, tier, price cap, amenities, proximity to a landmark or to the itinerary), transport and route/travel-time, things to do, weather and best season (dataset facts only), comparison, itinerary build/modify/undo, budget breakdown and cost reduction, general questions (answered honestly as out of scope), and clarification when unsure. The destination in focus persists, so "there", "those" and "make it cheaper" resolve against the current conversation. The chat window shows "What I understood" (editable), contextual suggestion chips and cards for stays, transport and activities. Star ratings are **not** in the dataset: a "five-star" request is answered with the closest tier and says it cannot verify ratings. Failed operations return a friendly message and leave the trip unchanged.

## What was tested
- 185 pytest tests (57 cover the chatbot): data validation, KB queries, hard constraints and exclusions, score reproducibility, A* vs Dijkstra and heuristic consistency, BFS, beam search constraints, budget arithmetic, optimiser, replan preservation and undo, chat flows, API round-trips, ML pipeline.
- Mutation check: 8 of 8 deliberate bugs were caught by the suite.
- Live browser run (Playwright, Chromium): planner → compare → build itinerary → edit/remove → undo → re-plan (add a day) → save → reopen → chat ("make it cheaper") → How TripWise Thinks → Discover; mobile width has no horizontal scroll; no application console errors.

## Known limitations
- Sample data only (see note above). Some destinations have few attractions, so longer trips can contain light or free days; the planner says so rather than padding.
- Chat understanding is rule-based, optionally assisted by Gemini (off without a key); unusual phrasing may be misread (use "What I understood" to correct). Accommodation has no star ratings, reviews, links or availability; weather is dataset climate/seasons only, not live. Each destination has one stay per tier, so "a few" results include the nearest alternative tiers (labelled).
- Beam search is not proven optimal. A* is optimal only on the modelled graph (edges ≈ straight line × 1.3).
- Stravl model: ROC-AUC 0.7235 vs 0.7036 for a popularity baseline (modest); covers only 5 sample destinations; informational, not part of the ranking. Its probabilities for sparse inputs sit below the dataset base rate (domain shift).
- Photos load at runtime from Wikipedia and map tiles from OpenStreetMap; both are blocked in the build sandbox, so they were **not verified visually** (gradient/fallback paths were). Needs internet.
- No authentication or multi-user separation; trips live in a local SQLite file.
- FastAPI `on_event` startup hook emits a deprecation warning.


## Chat-first interface

The homepage (`/`) is the chat. Everything else lives in a collapsible sidebar (a drawer on mobile): Destinations, Trip planner, My itinerary, Saved trips, How TripWise thinks, About. Chat answers show inline cards with contextual actions ("View all stays", "Open itinerary", "View budget breakdown", "Compare options") that open the existing pages. Conversation state lives in `lib/chat.tsx` so it survives navigation; "New chat" never deletes earlier conversations, which are listed per browser. See `docs/GEMINI.md` for the optional server-side Gemini understanding layer.

### Place and accommodation resolution

One pipeline handles every place and property name (`nlp.py`: `find_unsupported_place`, `parse_stay_query`, `match_stay_name`): known destinations resolve to stable ids; a city that exists only as a starting point (e.g. Chennai, Hyderabad) is reported honestly as having no attractions or stays; a property name is looked up in the accommodation records and, if found, locates itself; nothing unknown is ever replaced by another place. Follow-ups such as "show luxury options instead" keep the destination, and "make it <other destination>" re-plans while keeping origin, budget, days and travellers. Limitation: the sample dataset has 16 destinations and its stay records are generic fictional placeholders, so named hotels will usually not be found.


### Gemini (optional)

Gemini can be enabled as a language-understanding layer; the dataset and planning algorithms still produce every result, and the rule-based chatbot is the automatic fallback. Setup, security and fallback details: `docs/GEMINI.md`. Put `GEMINI_API_KEY` in `backend/.env` (see `.env.example`); never commit it.
